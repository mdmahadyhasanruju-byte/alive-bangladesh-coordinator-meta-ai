## Vision

Anyone can continue from anywhere; the weakest soul ever can continue through meUus. aLive Bangladesh is a narrow first proof of one evidence-linked coordination workflow within that broader vision.

## Mapping

| meUus idea | aLive Bangladesh first proof |
|---|---|
| Truth Protocol | Evidence linker attaches source references; deadlines remain null unless explicit and unambiguous. |
| Privacy | Synthetic-only public-demo fixtures, consent checkboxes, and a 30-day retention statement for demo data. The in-memory prototype does not yet implement scheduled deletion. |
| Time Mapping | A field visit carries a creation timestamp and can record past observations, the present need, and an explicit future commitment or deadline. |
| Four Dimensions | Need, evidence-backed description, commitment, and anticipated impact. Impact remains a draft, not a verified outcome. |
| DLAS 5 Levels | Narrow MVP mapping: need → description → evidence → follow-up → commitment. This is a provisional mapping, not the complete DLAS implementation. |
| Production Stack | This acting app builds with Next.js 16.4.3. Matching production-stack parity with the separate meUus.app repository is NOT VERIFIED. |

## Boundary

aLive is a narrow MVP proving one verifiable workflow, not full meUus. Full meUus still needs a live database, authentication, `risk_flags`, governed actions, counselor roles, mobile and offline-first support, and local policy review. The aspiration of 100+ languages requires per-language evaluation before quality or coverage claims.
